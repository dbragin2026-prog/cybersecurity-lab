# День 3 - Процессы в Linux

## Что изучил

- ps aux - просмотр запущенных процессов
- ps aux | grep - поиск конкретного процесса
- ps aux | --sort=-%cpu - сортировка процессов по загрузке CPU
- top - просмотр процессов в реальном времени
- kill - заверение процесса

## Основные поля процесса

- USER - пользователь, от имени которого запущен процесс
- PID - идентификатор процесса
- %CPU - использование CPU
- %MEM - использование памяти
- TTY - терминал процесса
- STAT - состояние процесса
- COMMAND - команда запуска

## Мини-расследование

Создал тестовый процесс sleep 300

Нашел его через ps aux | grep sleep

Определил:

- Пользователя
- PID 
- Команду
- терминал из которого был запущен процесс

После анализа завершил процесс с помощью kill <PID>

# Главный вывод

При анализе процессов важно смотреть не только на название процесса 

Нужно проверять 

- кто его запустил 
- PID
- команду 
- путь к исполняемому файлу
- аргументы запуска 
- потребление CPU и памяти
- соответствует ли процесс нормальной активности системы 

В SOC подозрительный процесс может быть признаком компрометации системы
